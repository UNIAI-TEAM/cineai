# 用户端多语言（i18n）

用户端 `frontend/` 支持中文（zh）、英文（en）、越南语（vi）三种界面语言，地位对等。产品方向是逐步以越南语与英文为主，中文仅在后端逻辑依赖处保留（例如模板 `name` 作为主值）。

## 语言选择规则

- **中文暂时关闭**：顶栏只显示越南语 / 英文（`ENABLED_LOCALES = ['vi', 'en']`），中文文案保留不删；恢复时把 `'zh'` 加回 `ENABLED_LOCALES` 即可。
- 首次进入按浏览器 `navigator.language` 判定：`vi*` → vi，其余（含 `zh*`）→ en；取不到时默认 vi（`src/i18n/detect.ts`）。已存的 `zh` 偏好在关闭期间被忽略。
- 顶栏切换后写入 `localStorage['printfilm.locale']`，之后优先手动选择。
- 切换时同步 `<html lang>`、`document.title` / `meta[name=description]`，日期按 `LOCALE_DATE` 格式化（`formatDateTime`）。

## 文案组织

```
src/i18n/
  detect.ts        Locale 类型、LOCALES、浏览器识别、持久化
  context.tsx      I18nProvider / useI18n()：t(path, vars)、m（当前语言整包）、locale、setLocale
  lookup.ts        点路径取值 + {var} 插值
  messages.ts      messages[locale]
  locales/
    zh.ts en.ts vi.ts          各语言索引，把下面各命名空间 spread 成一个对象
    {zh,en,vi}/shell.ts        壳层：common / dialog / nav / footer / auth / settings / status / shotStatus
    {zh,en,vi}/pages.ts        首页、帮助、联系、工具中心、定价、历史、漫剧列表、法律页
    {zh,en,vi}/studio.ts       科普/获客短视频：新建项目页、风格配置页
    {zh,en,vi}/studioBoard.ts  分镜页、成片编辑页
    {zh,en,vi}/billing.ts      支付弹窗、余额卡、用量/充值记录、余额不足提示
    {zh,en,vi}/settingsPanels.ts 账号设置各面板、模板页、分类标签（categories）
    {zh,en,vi}/errors.ts       接口错误码文案 + 漫剧生成失败提示（dramaGenError）
    {zh,en,vi}/dramaProject.ts 漫剧项目工作区、大纲/分集步骤、项目设置、Seedance 规则弹窗
    {zh,en,vi}/dramaAssets.ts  漫剧资产库、资产步骤、音色绑定
    {zh,en,vi}/dramaEpisode.ts 分集编辑页、字幕板、分段播放器、运镜词库展示名
    {zh,en,vi}/dramaCanvas.ts  自由画布与分集分镜画布
    {zh,en,vi}/dramaGen.ts     漫剧生成队列、任务详情
```

漫剧里落库的中文默认名（画布节点「新角色」、项目「自由画布项目」、导入「未命名」、分集「第N集」、「节点 N」「资产 N」「某某音色」等）保持中文原值，只在展示时翻译：`displayDramaTitle()` / `displayEpisodeName()`（`lib/dramaWorkflow.ts`）、`displayDramaAssetName()`（`lib/dramaLibraryAssets.ts`）、`canvasNodeDisplayLabel()`（`pages/drama/canvas/canvasTypes.ts`，非节点默认名交给 `displayDramaAssetName`）。前端新写入的音色默认名 / 绑定标签按当前界面语言生成。运镜词库 `insert` 为写入脚本的协议前缀，保持中文（插入编辑框时经 `toDisplayScript` 显示为界面语言，保存时换回中文）；`label` / `hint` 按界面语言显示。

- `Messages` 类型取自 `typeof zh`，因此 **三种语言的 key 树必须完全一致**（新增文案要三份一起加）。
- 组件内用 `const { t, m } = useI18n()`；数组/对象类文案用 `m.<ns>.<key>`。
- 非 React 的 helper（`lib/*.ts`）用 `getActiveLocale()` + `messages[locale]`（参考 `lib/status.ts` 的 `STATUS_CN` Proxy），或把 `t` / `m` 作为参数传入。
- `t()` 对空串返回空串，只有 key 不存在时才回退为 path 本身。
- 非中文界面下的兜底：模板 / 音色译文缺失时先试另一种已开放语言（vi↔en）再回落中文；未登记且含汉字的模板分类显示「其他」；漫剧生成失败原文含汉字时显示已翻译说明（原文在「查看原始错误」里）；无错误码的 401 统一提示「登录已失效，请重新登录」。
- 不要翻译：发给后端 / 大模型的提示词与协议标记（`【字幕：…】`、`@duration`、风格 prompt 等）、与后端数据比较的值（状态码、`pipeline_mode`、分类 key 如 `获客`、chips 选项值）、匹配后端报错的正则。
- 大块静态内容（宣传页 `lib/methodLanding.ts`、法律条款 `lib/legalContent.ts`）按 `Record<Locale, …>` 组织。

## 越南语文案质量

越南语**不得逐字直译**。写文案前先读 [I18N_GLOSSARY_VI.md](./I18N_GLOSSARY_VI.md)：其中有必须遵守的术语表（如 获客 →「bán hàng / tìm khách hàng」、钩子 →「hook」、卖点 →「ưu điểm sản phẩm」、上游 →「nhà cung cấp mô hình」）与写作原则（短句、口语、行业里通用的英文词保留）。一个概念全站只用一种叫法。

## 数据库中的模板名称

模板 `templates.name` / `description` 仍为中文主值，另有 `i18n` JSON 列：`{"en": {"name", "description"}, "vi": {...}}`。

- 内置模板译文在 `backend/app/services/templates_i18n.py`，`seed_templates()` 新插入时写入；已有记录仅在 `i18n` 为空时补齐，后台改过的不覆盖。
- 列由 `_apply_schema_patches()` 追加（additive DDL）；`tests/test_template_i18n.py` 保证每个内置模板都有 en / vi。
- 用户端 / 管理端 API 均返回 `i18n`；管理端 `AdminTemplateCreate/Patch` 可写入该字段（管理界面表单暂未提供编辑入口）。
- 前端一律通过 `lib/templateI18n.ts` 的 `templateName(tpl)` / `templateDescription(tpl)` 取展示文案，缺失时回落中文。

音色目录（`backend/app/services/voices.py`）同理：`label` 为中文主值，`label_i18n = {en, vi}` 供展示，前端用 `localizedLabel(voice)` 取值。

## 接口错误码

后端业务错误统一用 `app/errors.py` 的 `AppError(code, **params)`，响应体为 `{detail, code, params}`：`detail` 保持中文（兼容管理端、漫剧与开放 API），前端 `lib/apiError.ts` 的 `parseApiError()` 按 `code` 查 `i18n/locales/{zh,en,vi}/errors.ts` 翻译，查不到才显示 `detail`。

- 新增错误码：在 `ERRORS` 登记 `(状态码, 中文模板)`，并在三份 `errors.ts` 各加一行；`tests/test_app_errors.py` 会校验三份文案与目录一致。
- `params` 只放原始数据；金额用 `*_fen`（分），模板占位符去掉后缀（`need_fen` → `{need}`），前后端各自按展示货币格式化。
- 不要把上游 / 第三方报错原文放进 `detail` 或 `params`，记日志即可。
- 组件按 `err instanceof ApiError && err.code === '…'`（或 `err.status`）判断，不要比对文案。
- 开放 API / 外部客户端：`detail` 仅供人读，金额已按展示货币（VND / USD）格式化而非 `¥`，不要从 `detail` 解析数字或 id；请读 `code` 与 `params`（如余额不足的 `params.need_fen` / `params.available_fen`，任务目标错误的 `params.target`）。
- 生成队列（`dramaImageGenQueue` / `dramaVideoGenQueue` → 统一队列）失败时除 `error` 文案外还保存 `errorCode` / `errorStatus`，展示用 `formatDramaGenJobError(job)` 按码分类。
- 落库错误：任务失败时 `TaskRun.error_code` / `error_params` 存 `AppError` 的码与参数（其余异常仍存异常类名）；资产抽取失败在项目 params 存 `assets_seed_error_code` / `assets_seed_error_params`（`services/drama/seed.py` 的 `set_seed_error` / `clear_seed_error`）。前端展示落库错误用 `localizeStoredError(message, code, params)`，查不到码时显示原文。
- 落库错误码（短视频 / 工具 / 非漫剧任务）：`Project.error_code/error_params`、`ToolRun.error_code/error_params` 与 `error_msg` / `error` 一起写（原文仍存，供管理端与日志排查）；非 `AppError` 异常用 `services/exc_format.py` 的 `stored_error_fields(exc, default)` 归类——上游（`providers/*` 抛 `UpstreamError` 及其子类、httpx 网络异常）归为 `provider.timeout` / `provider.network_error` / `provider.content_rejected` / `provider.failed`，其余用默认码（任务 `task.execution_failed`，工具 `tool.run_failed`，合成 `project.compose_failed`）。科普项目写错误用 `services/project_errors.py`（`set_project_error` / `set_project_cancelled` / `clear_project_error`）。需要保留 `RuntimeError` 语义的运行期错误用 `AppRuntimeError(code, **params)`。漫剧任务（`domain=drama`）的 `TaskRun.error_code` 仍按旧规则（非 AppError 存异常类名），由漫剧侧自行分类。
- 401：`deps.py` 返回 `auth.login_required` / `auth.session_expired`（开放 API：`auth.api_key_missing` / `auth.api_key_invalid`）；开放 API 上游失败返回 `api.upstream_failed`，不回传服务商原文；视频任务查询（`GET /v1/tasks/{id}`）遇审核拦截 / 超时 / 网络等已登记码（`provider.content_rejected` / `provider.timeout` / `provider.network_error`）时返回该码 + 固定英文短句。
- 结构化字段代替中文拼接：扣费记录返回 `capability` 与 `context_kind` / `context_title` / `context_project_id`（`billing_label` / `context` 仅兼容保留）；额度告警返回 `milestone_fen` / `total_charged_fen`，前端自行拼标题与正文；找回密码邮件按请求的 `X-UI-Locale` 发 vi / en / zh。
- effect 里的兜底文案用 `i18n/translate.ts` 的 `translate()`（按当前语言），不要把 `t` 放进依赖，否则切换语言会重跑请求、清空表单。

## 管理端（admin/）

管理端只面向运营，**界面直接写越南语**，不接 i18n 框架（没有语言切换）。约定：

- 用户可见文案（JSX、placeholder、toast、确认框、状态映射 `lib/statusLabels.ts` / `lib/dramaLabels.ts`）一律越南语，术语同 [I18N_GLOSSARY_VI.md](./I18N_GLOSSARY_VI.md)；管理端可用「tác vụ」「quản trị viên」。
- 日期、数字用 `toLocaleString("vi-VN")`。
- 与后端比较或提交的值保持原样：状态码、模板分类 key（`科普`、`获客` 等，展示名见 `pages/TemplatesPage.tsx` 的 `TEMPLATE_CATEGORY_LABELS`）。
- 模板卡片优先显示 `i18n.vi` 的名称 / 描述，中文主值作为副标题。
- 计费依据按 `billing_basis` 在前端取 `billingBasisLabel()`，不直接显示后端 `billing_basis_label`（仍为中文）。
- `backend/app/api/admin/*` 中仅管理端使用的 `HTTPException.detail`（含 `get_current_admin` 的 403）已改为越南语。
- 共享 service 抛出的 `AppError`：`api/client.ts` 按响应里的 `code` / `params` 查 `lib/apiErrors.ts`（越南语，文案同用户端 `vi/errors.ts`），查不到才显示 `detail`。新增错误码时这份表也要加一行，`tests/test_app_errors.py` 会校验。管理端路由里 `except ValueError` 前要先 `except AppError: raise`，否则错误码会丢。
- 落库错误（科普项目 `error_msg`、TaskRun / 步骤 `error_message`、漫剧 params 里的 `*_error` 与 `generation.error`）：管理端接口同时返回 `error_code` / `error_params`（漫剧为 `AdminStoredErrorOut{message, code, params}`，见 `services/admin/stored_errors.py`），页面统一用 `components/admin/StoredErrorText.tsx` 展示——有已登记错误码时显示越南语译文，下方小字「Lỗi gốc: 码 · 原文」供排查；无码时照旧显示原文。

## AI 生成内容的语言

系统提示词保持中文（不降低提示质量），但**产出**跟随用户界面语言（vi / en），不再固定简体中文。统一入口 `backend/app/services/content_lang.py`（`tests/test_content_lang.py`）。

- **请求头**：用户端每个 API 请求都带 `X-UI-Locale: <locale>`（`src/lib/uiLocaleHeader.ts`，已接入 `src/api.ts` 与 `src/api/*` 的全部 `fetch`）。后端 `request_lang(request)`：`X-UI-Locale` → `Accept-Language` → 默认 `vi`。
- **漫剧项目语言**：创建项目时写入 `DramaProject.params["content_lang"]`（不加列）；`PATCH /api/drama/projects/{id}` 可传 `content_lang` 修改，整包回写 `params` 时若缺该字段会保留原值。项目详情返回 `content_lang`。后台任务（`services/drama/jobs.py` 等）一律用 `project_content_lang(project)` 读项目，不依赖请求；老项目没有该字段时按剧本原文 / 摘要 / 标题推断（含汉字 → zh，含越南语字母 → vi，否则 en）。
- **科普项目语言**：`projects.content_lang` 列（`_apply_schema_patches` 追加）记录创建时的界面语言（或用户显式所选，见下）；`kepu_content_lang(text, stored)`：文本含汉字 → zh，含越南语字母 → vi，否则（短主题、专有名词、纯英文）跟随记录的界面语言。拆镜与「AI 扩写主题」按它出旁白 / 标题。
- **用户显式选择内容语言（Việc P）**：
  - 漫剧：新建页（`DramaListPage`，默认跟随界面语言）传 `content_lang`；后端优先级 `body.content_lang` → `body.params.content_lang` → 界面语言。项目设置弹窗（`DramaProjectSettingsModal`）可改，`PATCH` 带 `content_lang`；只影响之后 AI 生成的内容，已有剧本 / 分镜不自动翻译（弹窗有提示）。自由画布创建不带选择，仍取界面语言。
  - 科普：新建页（`CreateProjectPage`）传 `content_lang`（同时用于「AI 扩写主题」`/api/content/expand` 的 `content_lang`）；后端写 `projects.content_lang` 并置 `projects.content_lang_locked=TRUE`（`_apply_schema_patches` 追加）。**实际语言一律用 `project_kepu_lang(project)`**：锁定时用所选语言（越南语主题 + 选英文 → 英文旁白），未锁定（老项目 / 未传）沿用 `kepu_content_lang` 推断。`ProjectOut` 返回 `content_lang_locked` 与 `effective_content_lang`。`PATCH /api/projects/{id}` 也接受 `content_lang`（生成中被 `project.locked_while_generating` 拦截），前端暂未在配置页放入口。
  - 可选项：vi / en；zh 只在项目本来就是中文或界面重新开放中文时出现（`frontend/src/lib/contentLang.ts`，文案 `contentLang.*`）。
  - 非法值（如 `fr`）→ `AppError("common.invalid_content_lang")`（400）；`null` / 空串视为未指定 / 不修改（`content_lang.parse_content_lang`，测试 `tests/test_project_content_lang.py`）。
- **提示词改写**：`drama_chat_json` / `drama_chat_text` / `run_task_*` 接受 `lang` 与 `lang_kind`；lang 非 zh 时 `localize_system_prompt()` 把「语言使用简体中文」等约束换成目标语言、把「N 个汉字 / N 字」换算为词数，并追加 `output_language_directive()`（中文书写的【输出语言】指令）。lang=zh 或 None 时提示词与旧行为完全一致。
- **结构标签不翻译**：剧本解析依赖中文标签（`### 场1-2`、`日/夜 内/外`、`出场人物：`、`△`、`空镜：`、`旁白（VO）：`），vi / en 项目也要求模型原样照写，只把标签后的内容写成目标语言；JSON key 与【…】协议标记同样保持原样。
- **生图 / 生视频提示词**：lang=zh 保持中文；vi / en 时画面描述（角色定妆 `visualImage`、场景 / 道具提示词、分镜画面行、Skill 优化后的提示词、科普 `img_prompt` / `video_prompt`）一律用英文，台词、旁白、字幕文字仍用内容语言（`lang_kind="visual"` + `visual_prompt_directive()`）。规则模板同理：后端 `seed_asset_params`、前端 `lib/dramaVisualPrompt.ts` 用 `Identity: / Role: / Tags: / Personality:`、`Scene: …`（前端未传语言时按文字是否含汉字判断）。
- **字幕 cue**：`【字幕：底部居中·简体中文·逐句轮换·与口播同步】` 的框架保持中文，语言词按台词语言换成「越南语 / 英语」（后端 `seedance_segments.drama_subtitle_cue()`、前端 `dramaSubtitleBoard.ts`）；Seedance 强制约束里的「烧录 X 字幕」同样按口播文字判断语言。
- **其他**：音色试听句按界面语言（`voices.preview_text_for_lang`，缓存按 voice + 语言区分）；角色音色描述、试听台词与漫剧聊天助手的回复按项目 / 界面语言。

## 漫剧后台任务：落库错误码与进度 key（Đợt 2B）

- **剧本 / 分集 / 分镜规划任务**：`params.<field>` 文案之外同时写 `<field>_code` / `<field>_params`（`summary_error`、`episode_content_error`、`episode_optimize_error`、`fragment_plan_error`；资产抽取沿用 `assets_seed_error*`）。写入走 `services/drama/job_errors.py` 的 `set_job_error` / `set_job_error_code`，重新运行成功后 `clear_job_error` 一并清掉；`user_job_error(exc)` 返回 `(文案, code, params)`，上游错误归类为 `drama.upstream_*`，未知错误为 `drama.gen_failed`（原始报错只进日志）。前端统一用 `lib/dramaJobError.ts` 的 `storedJobError(params, field)` 展示。
- **生图 / 生视频**：`params.generation` 失败时可带 `error_code` / `error_params`（`gen_error_fields` 只给能确定的分类：`AppError`、超时 `drama.gen_timeout`、网络 `drama.gen_network`；其余不带码，前端继续按原文细分审核 / 音频过短等）。任务平台的 `task.error_code` 也改为已登记码（`drama.prev_shot_failed`、`drama.fragment_changed`、`drama.gen_skipped_done`、`task.missing_provider_task`、`task.video_poll_timeout`、`task.upstream_failed`）。前端生成队列只把**已登记**的码（`registeredErrorCode`）存入 `errorCode`，`formatDramaGenJobError` 先按码分类，未登记的码（如异常类名）退回按原文分类。
- **进度文案**：`params.generation.message` 旁边写 `message_key` / `message_params`（`gen_progress(key, 中文文案, **params)`），前端 `dramaGen.msg.<key>` 翻译；前端不认识的 key 回退显示 message 原文。
- **资产提示词刷新失败**：新增 `llm_error_items` / `params.assets_seed_llm_error_items`（`[{kind, name, code, params}]`），旧的字符串列表保留；前端 `seedLlmErrorLines` 新数据按码翻译，老数据只显示「类型 “名称”」，不再显示原始报错。
- **默认名称**：`services/drama/naming.py` 按项目内容语言生成集名（「Tập N」/「Episode N」，zh 仍为「第 N 集」）、未命名资产 / 音色、画布节点名，以及开幕叠字里的集号（`【片头·集号叠字】Tập N`，标记本身不翻译）。判断占位集名用 `is_default_episode_title`（三种语言都认）。
